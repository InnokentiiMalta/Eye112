# 🚀 Оптимизация YOLO Fire Detector

## ✅ Что оптимизировано

### 1. Динамический импорт ONNX Runtime
- ONNX Runtime загружается **только при нажатии на вкладку YOLO**
- Основной бандл уменьшен с 270KB до 262KB
- ONNX Runtime вынесен в отдельный chunk (403KB, загружается по требованию)

### 2. Упрощённая предобработка
- Убран тяжёлый letterbox маппинг
- Используется простой resize для скорости
- Минимум операций с Canvas API

### 3. Упрощённый детектор
- Убран Web Worker (для начала)
- Прямой инференс в основном потоке
- Меньше накладных расходов

### 4. Lazy loading компонентов
- YOLO компоненты загружаются только при необходимости
- Динамический импорт класса детектора

## 📊 Результаты оптимизации

**До:**
- Основной бандл: 270KB
- ONNX Runtime: встроен в основной бандл
- Загрузка: сразу при открытии приложения

**После:**
- Основной бандл: 262KB (-8KB)
- ONNX Runtime: отдельный chunk 403KB (загружается только при использовании YOLO)
- YOLO детектор: отдельный chunk 2.8KB
- Загрузка: ONNX Runtime загружается только при нажатии "🔥 YOLO"

## 🚀 Быстрый старт

### Шаг 1: Скопировать WASM файлы

```bash
mkdir -p public
cp node_modules/onnxruntime-web/dist/*.wasm public/
```

### Шаг 2: Получить модель

Скачайте модель с Hugging Face или конвертируйте свою:

```bash
pip install ultralytics
```

Создайте `convert.py`:
```python
from ultralytics import YOLO

model = YOLO("best.pt")
model.export(format="onnx", opset=12, dynamic=True, simplify=True)
```

Запустите: `python convert.py`

### Шаг 3: Разместить модель

```bash
mkdir -p public/models
cp model.onnx public/models/fire-smoke.onnx
```

### Шаг 4: Запустить

```bash
npm run dev
```

Откройте браузер → нажмите "🔥 YOLO" → загрузите модель → протестируйте!

## 🎯 Производительность

- **Время инференса:** 200-500 мс на среднем ПК
- **Загрузка ONNX Runtime:** ~1-2 секунды (один раз)
- **Размер WASM:** ~28MB (загружается автоматически)
- **Использование памяти:** ~200-300MB во время инференса

## 🔧 Дальнейшая оптимизация

Если нужно ещё больше ускорить:

1. **Вернуть Web Worker** - инференс в отдельном потоке
2. **Использовать квантизованную модель** - INT8 вместо FP32 (в 4 раза меньше)
3. **Кэшировать модель в IndexedDB** - не загружать каждый раз
4. **Использовать более лёгкую модель** - YOLOv8n вместо YOLOv8s

## 📝 Примечания

- WASM файлы (28MB) загружаются автоматически при первом использовании YOLO
- ONNX Runtime кэшируется браузером
- Модель загружается один раз и кэшируется в памяти
- При переключении вкладок YOLO не выгружается (быстрое переключение)

## 🐛 Решение проблем

### Предпросмотр не запускается

```bash
# Очистите кэш и пересоберите
rm -rf node_modules/.vite
npm run build
```

### Ошибка загрузки WASM

Убедитесь, что WASM файлы скопированы:
```bash
ls public/*.wasm
```

Должны быть файлы:
- ort-wasm.wasm
- ort-wasm-simd.wasm
- ort-wasm-threaded.wasm
- ort-wasm-simd-threaded.wasm

### Медленная загрузка

- Первое использование YOLO загружает ~28MB WASM
- Последующие использования быстрее (кэш браузера)
- Можно использовать Service Worker для предзагрузки
